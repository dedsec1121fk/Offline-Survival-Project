# Offline information cache: save the guidance you may need after the network disappears

## Cache stable references, not live conditions
Store local copies of emergency numbers, household plans, equipment manuals, medication lists, maps and official hazard guidance that remains useful offline. Do not treat a saved weather forecast, evacuation order or shelter list as current after its timestamp expires.

## Put a visible “checked” date on external guidance
The project’s official-source index should show when links were last verified. When the internet is available, refresh time-sensitive pages and note their date. A downloaded document without context can outlive the rule it describes.

## Prefer common readable formats
Plain text, Markdown, PDF and images are usually more resilient than a web app that needs online scripts. Test files in airplane mode. Keep the most critical pages small enough to open on an older phone with limited memory.

## Separate official source from project interpretation
The manuals can summarize operational implications, but keep the source ID and official link so a user can verify when connectivity returns. Do not copy large proprietary documents into the project without permission.

## Back up the cache with the project
Include offline references in the same backup/restore plan as the Command Center, but avoid storing sensitive personal documents in a publicly shared release folder. Public knowledge and private state have different security requirements.

## Refresh after major policy or product changes
Emergency-number capability, shelter policy, medication instructions and manufacturer procedures can change. Review the source map at each release and retire obsolete references rather than accumulating conflicting versions.
