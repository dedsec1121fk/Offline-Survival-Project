# Neighborhood Communications Net

A small check-in network works best when participation is voluntary, privacy boundaries are explicit and messages carry only actionable information.

### Agree the scope before an incident
Write who is participating, the normal check-in window, the primary channel, one fallback, and which person can relay a message if direct contact fails. Do not collect medical, identity or location details that neighbors have not chosen to share.

### Use a compact status code
Design plain-language statuses such as “OK / need contact / need practical help / leaving area.” Define each one so it cannot be mistaken for a medical diagnosis or request for emergency services.

### Rumor firewall
A relay message keeps its source and time: “City alert, 14:20” is different from “someone heard the bridge is closed.” Mark unverified claims and avoid forwarding them as facts. Critical official instructions should point back to the issuing authority when possible.

### Missed contact
If a participant misses a check-in, follow the level of follow-up they previously agreed to. A neighborhood network should support people, not become a surveillance system or substitute for emergency services.
