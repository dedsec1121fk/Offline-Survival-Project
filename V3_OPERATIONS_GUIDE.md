# Offline Survival Project — v3 Operations Guide

## Design goal

Version 3 is meant to turn stored knowledge into a repeatable household operating system. The database tells you what to research and review; the Command Center helps you record decisions, resources, alternates, responsibilities and practice results.

## Recommended setup order

1. Complete **Household Profile** and the base preparedness checklist.
2. Select realistic hazards in **Risk Board**.
3. Add supplies and expiries to **Inventory**.
4. Build contacts, primary/backup communication methods and meeting points.
5. Complete **Health Continuity** only with information you deliberately want stored locally.
6. Save an origin and route-critical waypoints in **Navigation**.
7. Add protected-copy locations to the **Document Register** without storing credentials or secret keys.
8. Create recurring **Maintenance** tasks for anything that degrades, expires, discharges or needs periodic testing.
9. Assign primary + backup household roles.
10. Run one **Training** drill and turn the debrief into concrete checklist/maintenance tasks.
11. Export a full encrypted-by-you backup to protected storage; optionally export a redacted template for sharing.
12. Print an emergency binder if paper redundancy is useful for your household.

## Stress-use rules

- Prefer short facts, timestamps and explicit owners.
- Keep a primary and backup method for critical functions.
- Separate verified information from assumptions/rumors.
- Do not consume all reserves during the first phase of a disruption.
- Recheck the environment and official instructions before following an old plan.
- Use the incident log when decisions change so the reason is not lost.

## What the project deliberately does not do

- It does not replace emergency services or official alerts.
- It does not diagnose illness, prescribe treatment or calculate medication doses.
- It does not provide an authoritative street/topographic map.
- It does not guarantee a phone compass is correct.
- It does not encrypt exported backups for you.
- It does not authenticate users if you deliberately expose the local server to a LAN.

# Ελληνικός Οδηγός Λειτουργίας v3

## Στόχος σχεδιασμού

Η v3 μετατρέπει την αποθηκευμένη γνώση σε επαναλαμβανόμενο σύστημα λειτουργίας νοικοκυριού. Η βάση δείχνει τι πρέπει να μελετήσεις· το Command Center σε βοηθά να καταγράψεις αποφάσεις, πόρους, εναλλακτικές, υπευθυνότητες και αποτελέσματα ασκήσεων.

## Προτεινόμενη σειρά εγκατάστασης σχεδίου

1. Συμπλήρωσε **Household Profile** και βασικό checklist.
2. Επίλεξε ρεαλιστικούς κινδύνους στο **Risk Board**.
3. Κατέγραψε εφόδια και λήξεις στο **Inventory**.
4. Φτιάξε επαφές, κύριες/εφεδρικές επικοινωνίες και σημεία συνάντησης.
5. Συμπλήρωσε **Συνέχεια Υγείας** μόνο με πληροφορίες που επιλέγεις να αποθηκεύσεις τοπικά.
6. Αποθήκευσε αφετηρία και κρίσιμα waypoints στην **Πλοήγηση**.
7. Κατέγραψε τοποθεσίες προστατευμένων αντιγράφων εγγράφων χωρίς κωδικούς ή μυστικά κλειδιά.
8. Δημιούργησε επαναλαμβανόμενες εργασίες **Συντήρησης**.
9. Ανάθεσε κύριους και εφεδρικούς ρόλους.
10. Τρέξε μία άσκηση **Εκπαίδευσης** και μετέτρεψε την αποτίμηση σε συγκεκριμένες εργασίες.
11. Εξήγαγε πλήρες backup και προστάτεψέ το με δική σου ασφαλή αποθήκευση.
12. Εκτύπωσε emergency binder αν χρειάζεσαι έντυπη εφεδρεία.

## Κανόνες χρήσης υπό πίεση

- Σύντομα γεγονότα, timestamps και σαφείς υπεύθυνοι.
- Κύρια και εφεδρική μέθοδος για κρίσιμες λειτουργίες.
- Διαχώρισε επιβεβαιωμένες πληροφορίες από παραδοχές/φήμες.
- Μην καταναλώνεις όλες τις εφεδρείες στην πρώτη φάση.
- Επανέλεγξε περιβάλλον και επίσημες οδηγίες πριν ακολουθήσεις παλιό σχέδιο.
- Κατέγραψε στο incident log γιατί άλλαξε μία απόφαση.

## Τι δεν κάνει σκόπιμα το project

- Δεν αντικαθιστά υπηρεσίες έκτακτης ανάγκης ή επίσημες ειδοποιήσεις.
- Δεν κάνει διάγνωση, συνταγογράφηση ή υπολογισμό δόσης φαρμάκων.
- Δεν παρέχει επίσημο οδικό/τοπογραφικό χάρτη.
- Δεν εγγυάται ακρίβεια πυξίδας κινητού.
- Δεν κρυπτογραφεί μόνο του τα exported backups.
- Δεν παρέχει authentication αν εκθέσεις σκόπιμα τον local server στο LAN.
